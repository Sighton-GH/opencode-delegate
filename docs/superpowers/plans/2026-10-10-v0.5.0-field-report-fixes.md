## Not fixed, and why

- **14(b), a separate data directory per run.** That would split opencode's
  auth and session store across runs. Instead the error gets its own exit
  code and the README says what contends for the database.
- **17 at the source.** Whether the model or opencode's edit tool decodes
  the escape twice is not known. Only detection and a brief-side check are
  shipped.
- **Why some v0.4.0 wrappers exited with no output.** Not verified. In a
  probe, opencode sent no signals to the wrapper's process group. 0.5.0
  closes every path that could do it silently: the server is in its own
  process group, signals and internal failures are reported, and the
  collect phase runs without `errexit`. The next occurrence will name its
  cause.
- **D53, D57.** The host's memory watchdog killing background jobs is
  outside the plugin.
- **Built workspace output (D58).** Workspace links now resolve into the
  worktree, whose build output (`dist/`) does not exist until something
  builds it. Gates that read built output need a build step or `--install`.

## Review round

An independent review of the bin diff found five defects. All five were
fixed, with tests:
- **A bogus "internal error" line.** It was printed after every normal
  non-zero exit, because the ERR trap records harmless failures too.
- **No self-heal for a deleted worktree.** A worktree deleted by hand could
  not be re-created; git still had it registered.
- **Signals during provisioning.** A signal during `--install` stranded the
  worktree. The traps were installed after provisioning.
- **A non-atomic lock.** Two dispatches started together could both take it.
- **Title-agent errors.** opencode's title agent (`small=true`; 97 of 943
  stream errors in one machine's opencode log) could trip the rate-limit
  watchdog.

With the title, prune and exit-handler fixes undone in a scratch copy, the
new checks fail (5 failures); with them, 259/259 pass.
